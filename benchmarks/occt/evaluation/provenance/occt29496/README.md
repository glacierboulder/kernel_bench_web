# 翼面与机体做布尔截交时，闭合环缺少一条短边

[自然父版](https://github.com/Open-Cascade-SAS/OCCT/commit/e3744452bb60730ebf3e00e366e961f17e9ca3ec)、[上游修复 #29496](https://github.com/Open-Cascade-SAS/OCCT/commit/7797eb389a518e537e52eab9a88081be430a6048)、[同提交实际更新的 bug25994](https://github.com/Open-Cascade-SAS/OCCT/blob/7797eb389a518e537e52eab9a88081be430a6048/tests/bugs/modalg_7/bug25994)。采用其原始机体与翼面，`bfillds` 后用 `bbop sect 4` 取截面，并在**实际得到的 sect 对象**上检查自由端点。上游该行使用另一变量名，不能直接作为本题已验证闭环的依据。

| 截面 | B：顶点/边/自由端点，长度，最大容差 | F：同列 |
| --- | --- | --- |
| 原始位置 | 3/2/2，620.017，0.000213156 | 3/3/0，620.026，0.000024994 |
| 同时平移 (-2,6,3) | 3/2/2，620.017，0.000213156 | 3/3/0，620.026，0.000024994 |

自然版本均正常完成运算。四例都要求拓扑数正确、自由端点为零、总长绝对误差小于 0.001、最大容差小于 0.00005。仅看总弧长易漏掉约 0.009 的闭合小段，不能代替端点或拓扑检查。

**隔离依据。** 带起步点的参数曲面求交仍须把曲线与面域边界的交点落实到步进线上。B 只对部分曲面组合启用这一步，导致边界封闭段没有形成。上游 F 删除了跳过边界处理的开关；在自然 B 上，仅将 `IntTools_FaceFace` 调用中的对应实参固定为真，即足以在原例和邻域上逐数恢复 F 的结果，对照不变。参考补丁采用这项经独立编译验证的一行改动，不宣称是完整上游提交。

模型文件名、归档成员及两个模型的 SHA-256 均在 `source.json` 中。此题与首轮 #28491 的“单侧参数曲线存在却走了错误面域校验”不同：这里改变的是参数曲面的步进交线边界处理，使缺少的闭合边可以形成。公开命令为 `DRAWEXE -b -f reproduce.tcl`。

与本轮 #26841 的区别也经过版本关系核对：`git merge-base --is-ancestor 47e3009da9a2d86bdcf01f166e552adeee57af12 e3744452bb60730ebf3e00e366e961f17e9ca3ec` 返回 0，即 #29496 的坏基线已经包含 #26841 的修复。#26841 在已经生成交线后处理 MakeCurve/LineConstructor，本题保留该逻辑不动，只修正传入参数曲面步进求交的边界开关就能补回短边。
