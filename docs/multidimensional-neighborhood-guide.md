# OCCT 多维度邻域用例构造指南

本指南用于 issue 和组合题的后续构造与验收。邻域测试检验同一缺陷机制附近的修复是否成立；数量按适用维度、机制分支和已有证据决定，**每个 issue 最多 15 个邻域场景，没有最低配额**。计入已有邻域；矩阵中的独立输入/参数组合与操作顺序逐一计数，不能通过打包成一个脚本绕过上限。同一 issue 在当前五组的不同版本中出现时按编号汇总核对；历史归档套件的重复副本不另计。曲线上用于同一输入误差测量的采样点不算独立邻域场景。一个用例可以包含多个参数点，但必须逐点输出观测，不能用一个总返回码掩盖失败。

## 1. 先明确需要验证的机制

为每个 **issue 版本及源码基线** 写一张机制卡：

- 原始触发条件：操作、几何类型、参数域、容差、预期结果及已观测错误。
- 最早有证据支持的失败阶段：几何表示、求交、参数域拆分、拓扑装配、分类或生命周期。细机制是注释，不能用猜测替代运行证据。
- 必须同时满足的不变量：存在性、分支/连通性、域包含、3D/2D 一致性、精度及拓扑语义。
- 已知修复与可疑补丁：上游参考、单 issue 参考、历史 agent 补丁；注明证据强弱和版本兼容性。
- 预期受影响的输入维度，及不适用维度的理由。

例如 M27780 的端点方向 dot 为正只是一个子条件，还需检验 p-curve 经曲面映射后与 3D 曲线一致；M30082 的上报容差不是实际曲面残差的独立见证。

## 2. 选择维度，不做无目的笛卡尔积

| 维度 | 可用构造 | 预期关系或独立判据 | 常见陷阱 |
|---|---|---|---|
| 刚体等价变换 | 对全部输入施加同一平移、旋转、组合变换 | 拓扑/分支语义不变；输出逆变换后与原问题一致；解析支持方程仍成立 | 只移动一方会改变问题；旋转需要同步轴向/平面法向 |
| 尺度 | 以同一中心缩放，选择不同量级且仍在算法支持范围内 | 长度按 s、面积按 s²、体积按 s³；几何残差按模型单位定义 | 固定绝对常量可伪装容差；极小尺度可能进入另一个机制 |
| 几何参数 | 半径、轴间距、夹角、裁剪区间、球心位置等 | 解析解、独立高精度参考或可信配对关系 | 改参数后继续沿用原始分支数/体积期望 |
| 参数化与周期缝 | 周期起点变化、等价 U 区间、缝两侧、相反方向/交换输入 | 比较物理曲线/端点图和域包含，不盲目比较参数数字或曲线排序 | 全局闭环被拆成多段不一定错误；参数反向不等于几何反向 |
| 机制边界 | 近相切、短曲线、相近轴线、接近极点/退化端点 | 边界两侧分别推导预期；明确距离边界的量与数值余量 | 用一次噪声敏感观测硬定期望；把真正相切与近相切混为一谈 |
| 拓扑与否定对照 | 无交、单支、多支、空 Common、非空 Cut、有限面裁剪 | 存在性与预期连通分量、根分配、有效域一起检查 | 强行补支/扩大结果域也能满足“至少有曲线” |
| 操作/表示顺序 | 交换两面、分步与同时 Boolean、等价表示 | 明确语义等价前提后比较集合/体积/几何残差 | 浮点顺序不同允许数值差异；不能要求字节相同 |

按机制选择代表点。先做单维变化用于定位，再对高风险交互做少量组合，例如“缩放 × 周期缝”“平移 × 端点切向”。不要求覆盖所有维度，也不为每个 issue 机械复制同一组平移量。

## 3. 用例数量的停止条件

每个适用维度至少要有一个能区分相关错误修复的见证，边界行为必要时覆盖两侧；对范围较大的维度可选多个代表点。停止扩充前检查：

1. 机制卡列出的主要失效分支是否都有可执行见证？
2. 是否存在只对原始坐标、尺度、方向或某个特定分支数成立的补丁，当前用例仍完全放行？
3. 是否对几何存在性、精度和域包含用了足够独立的判据？
4. 新增点是否提供新信息，还是同一错误路径的重复执行？
5. 预算、运行稳定性、结果可解释性是否仍可接受？

按这些问题决定增加或停止，但任何 issue 的总场景数不得超过 15；达到上限而仍有缺口时，应优化代表点、替换冗余构造或明确未覆盖维度，不再增加。不能以“已经达到 N 个”作为充分性证明。覆盖矩阵要分别列出 **checkpoint 数、实际参数样本数、适用维度数**，不能把三者混为一谈。

## 4. Oracle 必须能拒绝错误补丁

### 4.1 多层判据

- 执行层：构建成功、runner 启动、输入加载、oracle 真正运行；这些不是几何通过。
- 结构层：存在性、拓扑有效性、连通分量、解析根覆盖及有限域包含。
- 几何层：3D 曲线与支持曲面、p-curve 映射与 3D 曲线的实际残差；对有解析式的输入直接计算方程残差。
- 数值层：模型尺度、单位、绝对/相对界限、有限数检查、端点与内部采样。

优先使用解析几何期望和可信测量。`Tolerance Reached`、`SetTolerance`、分支数、体积、dot、`IsDone`、`checkshape`、`TEST_DONE` 均不能单独代表完整正确性。量必须有限；NaN/Inf、缺失变量、空采样和未完成日志不可默认为通过。

### 4.2 独立性的强弱要写清

“另一个进程执行”与“另一个数学判据”是两个不同层次。用被修库的 `xdistcs` 等测量比读取该库的上报容差更独立，但仍与待修库共享实现。能写解析支持方程时，优先再加入直接方程残差；不能写时明确这一剩余依赖，不宣称完全独立验证。

检查采样时同时覆盖端点、靠近端点、内部和缝附近，按曲线域选点；固定有限采样不能证明连续域完备。误差较大或局部异常时加密并保留最差位置；不要仅换成更多均匀点便声称证明完成。

### 4.3 容差不能写成目标答案

将“几何残差上限”“上报容差的语义一致性”“历史参考值相等”分开。容差按量纲、输入尺度和参考证据确定；缩放之后重新推导，不能照搬数值。禁止因为某补丁未通过就调松阈值，或把较小上报容差自动认作更准确。

2026-10 DSH 的 M30082 补丁含 `aTolC = 6.5e-7`，旧 suite 全通过。新增测试必须以此类补丁为负对照：检查真实残差与上报值的一致性、不同尺度及参数下的行为。若未能拒绝它，应明确记录“负对照未被拒绝”，不能用新增用例数量掩盖这一事实。

## 5. 正/负对照与准入

每个候选记录 `proposed → executable → calibrated → registered` 的状态，并保留以下证据：

| 对照 | 作用 | 判定边界 |
|---|---|---|
| 锁定 B 基线 | 确认是否触及缺陷机制 | 不要求每个邻域都 B 失败；B 通过的健康邻域同样有用，应标明 |
| 可信参考修复 F | 验证预期可满足且 oracle 没写错 | 记录 commit、patch/tree hash；单 issue F 不自动等于完整组合参考 |
| 既有 agent 补丁 | 比较真实补丁的泛化缺口 | 不能用 agent 补丁自己通过来校准 expected 值 |
| 错误负对照 | 容差常量、错误分支/域扩展、丢 p-curve、只修 dot 等 | 选择与机制有关的负对照，记录究竟被哪项判据拒绝 |
| 无交/健康控制 | 防止总返回非空或硬补曲线 | 必须检查无结果时没有伪造/遗留结果 |

参考 F 不可用时，可用可审查解析解支持某些候选，但必须写明证据来源。仅能执行但预期未知、基线未核对、参考失败或数值不稳定的构造不进入 required；保持 candidate/unknown，并说明继续准入需要什么证据。不能用 build rc=0/no-crash 填充用例数。

## 6. 每个候选的记录模板

```yaml
issue: issue-id@version
source_id: locked-source-id
mechanism: 对应阶段与有证据的细机制
case: evaluation/cases/.../case.tcl
category: neighborhood
construction: 原始材料 / 解析构造 / 受控参数变体
parent_case: 原始用例或已有邻域
transform_or_parameters: 显式参数与单位
covered_dimensions: [rigid_transform, scale]
not_applicable_dimensions: {维度: 理由}
expected_relation: 由何种数学/可信参考推导
oracle: 存在性、域、分支、实际残差及阈值来源
measurement_dependencies: 解析计算 / 待修库测量 / 外部参考
sample_positions: 端点、内部、缝附近的规则与数量
baseline_result: geometry_pass / geometry_fail / runtime_error / unknown
reference_result: 结论、来源、hash、日志
negative_controls: 被拒绝的补丁和触发的断言，或未拒绝/未运行
admission: calibrated / candidate / unknown
resource_limits: 编译最多2任务，case wall/cpu/memory限制
```

每条运行还应保存输入、脚本、oracle、runner、patch、source tree 的 hash，原始日志与观察值。规模合理时固定代表参数；如用随机样本，保存种子、生成器版本、完整参数清单。可复现的固定样本不应冒充统计覆盖。

## 7. 组合题与版本接入

1. 针对每个 issue **版本** 构造邻域；同一编号在不同基线下不能直接共享通过结论。
2. 组合 suite 保留原始与回归检查，追加经准入的邻域；健康控制仍需保留其各自语义，不把无关回归改名成邻域凑数。
3. 已运行快照不改写。通常按 [题库维护规则](benchmark-authoring.md) 维护新 suite 版本；本轮用户明确允许直接扩充现有五组，因此保留原 group/suite ID 与所有旧检查并追加邻域，由 Git 跟踪变更。更新前后的 suite 文件 hash 和 checkpoint 清单须保留，历史成绩按原快照 hash 解释，不能仅凭相同 suite ID/version 判断测试集相同。数据库当前题目若需同步，先保存旧 payload，再只更新当前题目，不改历史 runs。
4. 公共输入与隐藏检查分离。隐藏脚本/负对照/期望只在 supervisor 冻结，不进入 agent 工作区。
5. 用 `support_files` 显式列出隐藏 helper 与输入依赖；路径须为安全的 bundle 相对路径，依赖一并冻结和计算快照 hash。不能依赖可变宿主路径或源码之外的偶然文件。
6. 校验 catalog、路径路由、hash 与快照，随后运行真实几何检查；静态通过只证明接入，不代表几何验收。

## 8. 结果分类与研究报告

至少区分：构建/依赖故障、输入或 runner 故障、超时/资源限制、oracle 未运行、几何失败、几何通过、参考值一致性未解。执行器的外层 `failed` 不能覆盖内层 `oracle.status=not_run`。

报告每个维度的实际观测、失败位置、未覆盖理由和负对照表现，保留原始证据。修复“基础设施”后原样重评原补丁；重新调用模型修复则是新尝试，不能覆盖旧结果。对新增邻域的结论只适用于该 suite 版本；旧套件成绩不追溯改写。
